# Data exchange: GPX export and backup folder

How to get your rides out of Wattspur and read them with other tools (B-177). There are two ways:

- **GPX export** of a single ride: a standard format that komoot, Strava, Garmin and most map tools read. **Stable.**
- **Backup folder** of the whole library (**File › Library Backup…**): everything Wattspur stores. Its manifest and the original files are stable; the database inside is Wattspur's internal storage and **may change with any version**.

A stable export of the whole library as JSON and CSV is planned separately (B-178, version open). Until then, the backup and the example script below are the way to read all rides at once.

## GPX export

**Ride detail › Export as GPX…** writes one ride as [GPX 1.1](https://www.topografix.com/GPX/1/1/).

| Element | Content |
|---|---|
| `gpx/@creator` | `Wattspur` |
| `metadata/name`, `trk/name` | The ride's name |
| `metadata/desc`, `trk/desc` | The bike's name, if the ride has one |
| `metadata/time` | Start of the ride, UTC |
| `trk/type` | `cycling` |
| `trkseg` | One segment per part of a merged ride, so the gap between the parts stays a gap. A ride that was not merged has one segment |
| `trkpt/@lat`, `@lon` | Degrees, 7 decimals (about 1 cm) |
| `trkpt/ele` | Altitude in metres, 1 decimal, where the source has one |
| `trkpt/time` | ISO 8601 in UTC, e.g. `2026-10-18T12:12:13Z` |
| `trkpt/extensions/power` | Watts, as Garmin and Strava write it |
| `trkpt/extensions/gpxtpx:TrackPointExtension/gpxtpx:cad` | Cadence (1/min), Garmin TrackPointExtension v2 (`http://www.garmin.com/xmlschemas/TrackPointExtension/v2`) |

Notes:

- Only points with a position are written. Speed and distance are not stored per point; every GPX reader computes them from positions and times.
- Cadence is written only where it was measured. In the charts Wattspur holds the last value between two measurements; that held value is not exported.
- Heart rate and temperature from imported GPX files are not exported yet.

## Backup folder

**File › Library Backup… › Back Up…** creates a folder named `Wattspur Backup 2026-10-27 1230`:

```text
Wattspur Backup 2026-10-27 1230/
├── manifest.json
├── default.store                      SQLite database (SwiftData)
└── .default_SUPPORT/                  hidden folder: larger data
    └── _EXTERNAL_DATA/
        ├── 2DB52B1E-9D2E-422D-A2D0-78196B7C29D0     e.g. an original FIT file
        └── 6AB9807E-C214-4935-9FC9-CA1724FD8E23     e.g. a ride's time series
```

The folder starting with a dot is hidden in Finder; press ⇧⌘. to show it.

### `manifest.json` (stable)

```json
{
  "appVersion" : "1.8.0",
  "build" : "1",
  "createdAt" : "2026-10-27T22:46:04Z",
  "format" : 1,
  "rideCount" : 76
}
```

| Key | Meaning |
|---|---|
| `format` | Format of the backup folder. `1` since Wattspur 1.7.1. A Wattspur that knows only a lower number refuses to restore it |
| `createdAt` | When the backup was made, ISO 8601 in UTC |
| `appVersion`, `build` | The Wattspur version that made it |
| `rideCount` | Rides in the library at that time, for the confirmation before a restore. May be missing |

### `default.store` (internal)

A plain SQLite 3 file in rollback-journal mode, so it opens on its own, also from a read-only disk. Open it **read-only**, for example `sqlite3 "file:default.store?mode=ro" ` or in Python with `uri=True`. Never write into a backup you may want to restore.

The schema is generated by SwiftData (Core Data underneath) from Wattspur's models. Tables and columns are listed below as of Wattspur 1.8. **They can change with any version**; only `manifest.json`, the original files and the GPX export are promised to stay. A test in the repository (`DataExchangeDocTests`) checks this page against a freshly made backup, so the page is right for the version it ships with.

#### Conventions

| What | How it is stored |
|---|---|
| Table names | `Z` + the model name in capitals: `Ride` → `ZRIDE` |
| Column names | `Z` + the property name in capitals: `startDate` → `ZSTARTDATE` |
| `Z_PK` | Row number, the key that other tables point to |
| `Z_ENT` | Number of the model; the mapping is in `Z_PRIMARYKEY` (`Z_ENT`, `Z_NAME`). Do not hard-code the numbers |
| `Z_OPT` | Change counter, internal |
| Relations | A column named like the relation holds the `Z_PK` of the other row: `ZRIDE.ZBIKE` → `ZBIKE.Z_PK` |
| Dates (`TIMESTAMP`) | Seconds since **1 January 2001, 00:00 UTC** (Apple's reference date), as a floating-point number. Unix time = value + `978307200`. In SQL: `datetime(ZSTARTDATE + 978307200, 'unixepoch')` |
| UUIDs (`ZID`, `…ID`) | 16 bytes. In SQL: `hex(ZID)`; in Python: `uuid.UUID(bytes=…)` |
| Booleans | `0` or `1` |
| Units | Metres, seconds, metres per second, watts, 1/min, kilojoules, as named below |
| `…RAWVALUE`, `…RAW` | The name of a choice, e.g. `ZBIKE.ZKINDRAWVALUE` = `gravel`. Listed below |
| Large data (marked *external*) | First byte `01`: the data follows in the column. First byte `02`: the rest is the name of a file in `.default_SUPPORT/_EXTERNAL_DATA/` (UTF-8, ends with a zero byte). SQLite decides which, by size |

Tables starting with `A` (`ACHANGE`, `ATRANSACTION`, `ATRANSACTIONSTRING`) are SwiftData's change history, and `Z_METADATA`, `Z_MODELCACHE` and `Z_PRIMARYKEY` are its bookkeeping. Ignore them.

#### Which rides to count

Wattspur's own totals use rides where `ZDELETEDAT IS NULL` (not in the trash), `ZISSAMPLE = 0` (not the sample ride) and `ZMERGEDINTO IS NULL` (not a part of a merged ride; the merged ride counts instead).

### `ZRIDE`

One row per ride, including parts of merged rides and rides in the trash.

| Column | Type | Meaning |
|---|---|---|
| `ZID` | UUID | The ride's id |
| `ZNAME` | text | Name, as shown in the list |
| `ZSTARTDATE` | date | Start |
| `ZTIMEZONEIDENTIFIER` | text | Time zone of the start, e.g. `Europe/Berlin`; empty until looked up |
| `ZIMPORTEDAT` | date | When the ride was imported |
| `ZDELETEDAT` | date | In the trash since; empty otherwise |
| `ZISSAMPLE` | bool | The sample ride from the first start |
| `ZSOURCEFORMAT` | text | Format of the original file: `fit` or `gpx` |
| `ZSOURCEIDENTIFIER` | text | Id from the source, e.g. Bosch's ride id from the file name; used to find duplicates |
| `ZSUMMARYESTIMATEDFROMGPS` | bool | Totals computed from the track because the source has none (GPX) |
| `ZATTACHEDSOURCENAME`, `ZATTACHEDSOURCEFORMAT` | text | A second file attached to the ride, e.g. a GPX next to the FIT |
| `ZSOURCEFILE` | → `ZSOURCEFILE` | The original file |
| `ZBIKE` | → `ZBIKE` | The bike |
| `ZRIDER` | → `ZRIDER` | The rider |
| `ZMERGEDINTO` | → `ZRIDE` | For a part: the merged ride it belongs to |
| `ZTIMERTIME` | s | Ride time (moving) |
| `ZELAPSEDTIME` | s | Total time including pauses |
| `ZDISTANCE` | m | Distance |
| `ZAVERAGESPEED`, `ZMAXSPEED` | m/s | Average and maximum speed |
| `ZAVERAGEPOWER`, `ZMAXPOWER` | W | Rider power |
| `ZBESTPOWER1MIN` | W | Best average power over one minute |
| `ZAVERAGECADENCE`, `ZMAXCADENCE` | 1/min | Cadence |
| `ZTOTALASCENT`, `ZTOTALDESCENT` | m | Ascent and descent |
| `ZMINALTITUDE`, `ZMAXALTITUDE` | m | Lowest and highest point |
| `ZWORKKILOJOULES` | kJ | Rider's work |
| `ZDEVICESERIALNUMBER` | number | Serial number in the file. Bosch writes a new one into every export, so it does not identify the bike |
| `ZSAMPLESDATA` | *external* | The time series, see [below](#time-series) |
| `ZOVERVIEWROUTEDATA` | data | Simplified route for the map of all rides; Wattspur's own binary format, internal |
| `ZPARSERVERSION`, `ZPEAKPOWERVERSION`, `ZOVERVIEWROUTEVERSION` | number | Versions of Wattspur's calculations, internal |

### `ZSOURCEFILE`

The original file of each ride, unchanged.

| Column | Type | Meaning |
|---|---|---|
| `ZID` | UUID | Id |
| `ZFILENAME` | text | File name at import, e.g. `Reinheim Rundfahrt-….fit` |
| `ZDATA` | *external* | The file's bytes: a FIT or GPX file you can save and open elsewhere |
| `ZRIDE` | → `ZRIDE` | The ride |

### `ZBIKE`

| Column | Type | Meaning |
|---|---|---|
| `ZID` | UUID | Id; `ZRIDER.ZACTIVEBIKEID` points to it |
| `ZNAME` | text | Name |
| `ZCREATEDAT` | date | Added |
| `ZKINDRAWVALUE` | text | `bike`, `mountain`, `road` or `gravel` |
| `ZISEBIKE` | bool | Has a motor |
| `ZCOLORRAWVALUE` | text | Colour of its symbol: `blue`, `orange`, `teal`, `purple`, `pink`, `green` |
| `ZMANUFACTURER`, `ZMODEL`, `ZDRIVEUNIT` | text | As entered |
| `ZBATTERYWH` | Wh | Battery |
| `ZWEIGHTKG` | kg | Weight |
| `ZPURCHASEDATE` | date | Bought |
| `ZSTARTKILOMETERS` | km | Odometer before the first ride in Wattspur |
| `ZISARCHIVED` | bool | Archived |
| `ZSORTORDER` | number | Position in lists |
| `ZSERIALNUMBER` | number | Only from early versions, internal |
| `ZRIDER` | → `ZRIDER` | Owner |
| `ZPHOTODATA` | *external* | Photo, JPEG, at most 1000 pixels on the long side |

### `ZRIDER`

| Column | Type | Meaning |
|---|---|---|
| `ZID` | UUID | Id |
| `ZNAME` | text | Name |
| `ZCREATEDAT` | date | Created |
| `ZWEIGHTKG` | kg | Weight |
| `ZHEIGHTCM` | cm | Height |
| `ZBIRTHYEAR` | number | Year of birth |
| `ZSEXRAWVALUE` | text | `male`, `female` or `unspecified` |
| `ZACTIVEBIKEID` | UUID | `ZBIKE.ZID` of the bike new rides go to |
| `ZPHOTODATA` | *external* | Photo, JPEG, at most 512 pixels on the long side |

### `ZGOAL`

| Column | Type | Meaning |
|---|---|---|
| `ZID` | UUID | Id |
| `ZMETRICRAWVALUE` | text | `distance`, `rides` or `ascent` |
| `ZPERIODRAWVALUE` | text | `week`, `month` or `year` |
| `ZTARGET` | number | Metres, number of rides, or metres of ascent |
| `ZCREATEDAT` | date | Created |

### `ZROUTEGROUP`

A saved route (B-121). Which rides belong to it is computed by Wattspur from their similarity, not stored.

| Column | Type | Meaning |
|---|---|---|
| `ZID` | UUID | Id |
| `ZNAME` | text | Name |
| `ZCREATEDAT` | date | Saved |
| `ZTHRESHOLD` | 0…1 | How similar a ride must be |
| `ZINCLUDEREVERSE` | bool | Rides the other way round belong to it too |
| `ZREFERENCERIDEID` | UUID | `ZRIDE.ZID` of the ride it was made from; that ride may be gone |
| `ZREFERENCEROUTEDATA` | data | The reference route, same internal format as `ZRIDE.ZOVERVIEWROUTEDATA` |

### `ZIMPORTRECORD`

The import log (**File › Import Log**, ⌥⌘L).

| Column | Type | Meaning |
|---|---|---|
| `ZID` | UUID | Id |
| `ZDATE` | date | When |
| `ZFILENAME` | text | File |
| `ZOUTCOMERAW` | text | `imported`, `updated`, `duplicate`, `unsupported`, `failed` or `attached` |
| `ZSOURCERAW` | text | `manual` (dropped or opened) or `folder` (watched folder) |
| `ZDETAIL` | text | Technical reason of a failure |
| `ZRIDEID` | UUID | `ZRIDE.ZID` of the ride, if one was made |
| `ZMOVEDTO` | text | Where the file went in the watched folder, e.g. `Failed/x.fit` |
| `ZRECORDKINDSRAW` | text | Records the ride broke, comma-separated |

### Time series

`ZRIDE.ZSAMPLESDATA` is a binary property list (Apple's `bplist00`): an array with one dictionary per second. Python reads it with `plistlib`, macOS with `plutil -p`.

| Key | Unit | Meaning |
|---|---|---|
| `time` | s | Seconds since `ZSTARTDATE` |
| `latitude`, `longitude` | ° | Position |
| `altitude` | m | Altitude |
| `distance` | m | Distance since the start |
| `speed` | m/s | Speed |
| `power` | W | Rider power |
| `cadence` | 1/min | Cadence, held between two measurements for the charts |
| `cadenceMeasured` | bool | `true` only where cadence was measured; use these for statistics |
| `heartRate` | 1/min | Heart rate, from some GPX files |
| `temperature` | °C | Temperature, from some GPX files |

Keys without a value are missing, not zero. A merged ride has the time series of all parts one after the other; the gaps between parts are gaps in `time`.

## Example: reading a backup with Python

[`wattspur_backup.py`](wattspur_backup.py) needs only Python 3's standard library. It lists the counted rides as CSV, or writes one ride's time series or original file:

```bash
python3 docs/reference/wattspur_backup.py "Wattspur Backup 2026-10-27 1230" > rides.csv
python3 docs/reference/wattspur_backup.py "Wattspur Backup 2026-10-27 1230" --samples 9F3C… > ride.csv
python3 docs/reference/wattspur_backup.py "Wattspur Backup 2026-10-27 1230" --original 9F3C… > ride.fit
```

The id is the ride's UUID from the first column of the list; its first characters are enough if they are unique.

## Example: SQL

All counted rides with bike, in the time zone of the computer:

```sql
SELECT r.ZNAME AS name,
       datetime(r.ZSTARTDATE + 978307200, 'unixepoch', 'localtime') AS start,
       round(r.ZDISTANCE / 1000, 1) AS km,
       round(r.ZTIMERTIME / 60) AS minutes,
       r.ZTOTALASCENT AS ascent_m,
       b.ZNAME AS bike
FROM ZRIDE r LEFT JOIN ZBIKE b ON b.Z_PK = r.ZBIKE
WHERE r.ZDELETEDAT IS NULL AND r.ZISSAMPLE = 0 AND r.ZMERGEDINTO IS NULL
ORDER BY r.ZSTARTDATE;
```

Kilometres per year:

```sql
SELECT strftime('%Y', r.ZSTARTDATE + 978307200, 'unixepoch') AS year,
       round(sum(r.ZDISTANCE) / 1000) AS km, count(*) AS rides
FROM ZRIDE r
WHERE r.ZDELETEDAT IS NULL AND r.ZISSAMPLE = 0 AND r.ZMERGEDINTO IS NULL
GROUP BY year ORDER BY year;
```
